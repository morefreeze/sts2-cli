# 紧凑地图与节点决策展示设计

## 目标

训练工作台的地图需要在不缩小节点点击区域、不牺牲路线辨识度的前提下显著缩短纵向长度，并让用户不必逐个点开节点就能看见该层实际做出的非战斗决策。

本次范围包括：

- 地图纵向层距从当前 180px 收紧到 88px。
- 节点旁固定显示一行实际决策。
- 卡牌、药水、遗物等名称后显示灰色效果说明；过长时单行省略。
- 鼠标悬停或键盘聚焦节点时，展示完整效果与全部备选项。
- 新评测日志保存事件、卡牌奖励、药水、遗物、商店和休息点的结构化决策证据。

地图路径选择不重复写成文本，因为金色路线已经表达该信息。战斗内出牌也不放进地图摘要。

## 交互设计

### 紧凑布局

- `MAP_ROW_GAP` 调整为 88px。
- 节点直径、横向列距、连线和点击热区保持现有尺寸，避免紧凑化影响可点击性。
- 移除地图上纵向堆叠的旧 delta 徽标；其信息转为节点旁的一行摘要或节点详情。
- SVG 高度按实际幕的行数计算；Act 1/2、Act 3、Act 4 继续使用各自真实行数。

### 节点旁摘要

每个已访问节点最多显示一行，按实际发生顺序合并该节点的非战斗决策，例如：

- `选：献血，获得最大生命`
- `卡：Pommel Strike` `造成 9 点伤害，抽 1 张牌…`
- `药：火焰药水` `对一个敌人造成 20 点伤害…`
- `休息：升级 Colossus` `伤害与格挡数值提高…`

决策名称使用正文强调色；效果说明使用灰色。整行超出可用宽度时用省略号截断，不增加地图行高。

同一节点存在多个决策时，优先显示最新的明确选择，并在末尾显示 `+N`；悬停层展示全部决策。节点详情仍保留完整的库存、差值和诊断信息。

### 悬停与键盘

- 鼠标悬停节点时显示浮层。
- 节点获得键盘焦点时显示相同浮层，`Escape` 关闭；焦点移走后关闭。
- 浮层列出已选项、完整效果和所有当时可选项；已选项用勾选和加粗区分。
- 点击节点仍打开现有详情面板，不改变既有导航。
- 浮层只使用文本节点渲染，不解释日志中的 HTML。

### 旧日志降级

旧日志没有完整备选项时不得猜测：

- 若库存差值能精确证明获得卡牌、药水或遗物，显示 `推导：获得 …`。
- 灰色效果说明只在元数据目录能用稳定 ID 精确解析时展示。
- 悬停层显示“该对局未记录备选项”。
- 无可靠证据时不显示决策摘要。

## 数据设计

### 选择方案

采用“把有界的结构化决策嵌入对应 visited node”的方案，而不是新增独立 `node_decision` 日志事件。

原因：

- 地图快照本来就是失败后必须落盘的最终权威视图；嵌入节点可随同终局快照一起提交。
- 节点坐标、库存前后状态和决策证据天然绑定，避免额外事件在重试、迟到 map reply 或跨幕时错配。
- catalog 的 511/513 路径可复用同一个 map snapshot 合同，不再引入第二套 join 身份。

### 节点字段

每个 visited node 可选包含 `decisions` 数组。单项结构为：

```json
{
  "kind": "event",
  "selected_id": "option-1",
  "selected_label": "献血，获得最大生命",
  "options": [
    {
      "id": "option-1",
      "label": "献血，获得最大生命",
      "effect": "失去 8 生命；最大生命 +8",
      "selected": true
    }
  ],
  "evidence": "recorded"
}
```

`kind` 仅允许：`event`、`card_reward`、`potion`、`relic`、`shop`、`rest`。所有 ID、标签和效果都使用 exact string、UTF-8 scalar 和长度上限；数组数量、总深度及序列化字节数沿用地图快照的有界策略。非法或超限条目单项丢弃，不影响玩法。

### 捕获时机

- 在发送会改变房间状态的选择命令前，从当前 state 记录可选项与效果。
- 命令返回后，用实际 command/response 确认 selected 项，再附到当前 visited node。
- 事件、奖励、商店和休息点允许同一节点记录多项决策，并保持实际顺序。
- 最终 `map_snapshot` 在 `outcome` 前刷新；失败、死亡或 reset_failure 仍使用已有原子追加和重试语义。
- 捕获失败只记录有界 warning，绝不阻止游戏命令，也不伪造 selected/alternatives。

### 效果文本

优先使用游戏状态或元数据目录中与稳定 ID 对应的本地化说明；不能精确解析时效果为 `null`。前端只展示已保存或精确解析的说明，不由名称猜测效果。

## 解析、API 与兼容

- `recorded_maps` parser 验证 `decisions` 的结构、上限和 JSON/UTF-8 安全性，并把它作为节点不可变快照的一部分。
- adapter 将结构化决策保留到 canonical recorded route nodes；无决策字段的历史快照继续可读。
- compact catalog 与完整 rescan 必须得到相同 capabilities、decisions 和 warnings。
- `/api/run/map` 在 recorded map 权威通过时原样返回有界 decisions；fallback generator 不制造备选项。
- map UI 同时支持新 decisions 和旧 delta-only 节点。

## 验证

先写失败测试，再实现：

1. producer：六类决策的 selected/alternatives/effect 与节点坐标绑定；失败终局仍在 outcome 前持久化。
2. 安全边界：恶意字符串、深层对象、超量 options、异常 Mapping 均 fail closed 且不影响游戏进程。
3. parser/adapters/catalog：旧日志兼容；511/513 parity；跨来源 join 不伪造决策。
4. HTTP：recorded-first 返回 decisions；不可信 recorded map 回退且不泄漏原始恶意字段。
5. 前端：88px 层距、一行省略、灰色效果、hover/focus 全备选、无 HTML 注入、旧日志推导标记。
6. 真实浏览器：使用实际 smoke run 检查 Act 1 完整地图高度、节点可点击性、浮层不遮挡当前节点和键盘访问。

## 非目标

- 不改训练算法、奖励、PPO、动作掩码或策略输入。
- 不在地图上展开战斗回合或逐张出牌。
- 不回填旧日志不存在的事件备选项。
- 不改变现有节点详情、诊断和基线比较的语义。
