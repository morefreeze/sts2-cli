# 游戏版本与角色优先的训练批次筛选设计

## 目标

训练工作台先确定比较口径，再选择训练批次。筛选顺序调整为：

1. 游戏版本
2. 角色
3. 当前批次
4. 基线批次

游戏版本和角色均为可选筛选条件，保留“全部版本”和“全部角色”。

## 布局

- 桌面端第一行显示“游戏版本”和“角色”，第二行显示“当前批次”和“基线批次”。
- “记录状态”放在批次选择之后，继续参与批次过滤。
- 移动端沿用现有响应式单列布局，字段顺序与桌面端一致。
- 当前批次与基线批次的帮助文案、键盘焦点和无障碍关联保持现有行为。

## 联动规则

- 游戏版本选项来自全部 cohort，保留“全部版本”。
- 角色选项来自当前游戏版本范围内的 cohort；选择“全部版本”时显示全部角色。
- 切换版本后，如果已选角色在新版本下仍存在则保留；否则重置为“全部角色”。
- 当前批次候选由游戏版本、角色和记录状态共同过滤。
- 筛选变化后，当前批次选择过滤结果中的服务端稳定排序第一项。
- 基线批次继续使用服务端提供的 `default_baseline_cohort_id`，并且只能来自当前过滤后的候选集合。
- 保留手动选择基线的既有行为；当手动选择不再属于候选集合时清空。

## 空状态与异常处理

- 没有匹配 cohort 时，当前批次显示“没有匹配批次”，基线显示“不比较基线”。
- 不沿用已经被新筛选条件排除的当前批次或基线批次。
- 格式异常的 cohort 字段继续通过现有 `filterValue` 归入“未标注”，不在前端猜测版本或角色。
- 比较兼容性和不兼容原因仍以服务端结果为准，前端不自行构造比较结论。

## 测试与验收

- 静态 DOM 契约验证版本、角色、当前批次、基线批次的视觉顺序。
- JavaScript 行为测试覆盖：
  - 版本变化收窄角色选项；
  - 可用角色选择被保留；
  - 不可用角色回退到“全部角色”；
  - 版本与角色共同过滤当前批次；
  - 当前批次和基线在候选消失时正确重选或清空。
- 运行完整 workbench 测试。
- 在真实浏览器中验证桌面布局、筛选联动、焦点保持和空状态。
