# CLAUDE.md

## Testing Requirements

Any code change MUST pass a full regression test before claiming completion:

```bash
# 5 games per character, ALL must complete (0 crashes/stuck); the five lanes run in parallel
.venv/bin/python python/run_batch.py --name regression --kind regression --games 5 --chars all
```

`run_batch.py` starts one `play_full_run.py` lane per character (3 solver threads each, `STS2_GAME_DIR` defaulted to the Steam install) and stays in the foreground until every lane has exited. Read the verdict from its closing summary: one line per lane with the results-row count and that lane's `Wins: …, Completed: N/N, …` line. Expected: `Completed: 5/5` for every lane (an incomplete lane is flagged `INCOMPLETE`; the launcher exits non-zero only if a lane process itself failed). `--chars Silent,Defect` runs a subset, `--dry-run` prints the lane commands without starting anything, and arguments after a bare `--` go to every lane (e.g. `-- --game-version v0.111.0`). SIGTERM/SIGINT on the launcher stops every lane. `--resume <batch dir|id>` continues a batch whose launcher died (reboot, kill): each unfinished lane restarts after its last completed seed and appends to the same files; finished lanes are skipped and the manifest records the resume.

Everything lands in `logs/batches/<name>-<YYYYmmdd-HHMMSS>/` (`manifest.json`, `lanes_status.json`, `<lane>.log`, `<lane>.jsonl`, `games/`), which the run workbench's 回归/评测 tab reads. **`logs/batches/` is kept** — `game_log.cleanup_old_logs()` only purges top-level `logs/*.jsonl` after 7 days, and the launcher copies every game's log into the batch's `games/` (`--keep-game-logs`), so nothing needs saving by hand. Don't start a second batch while one runs from this checkout (`pgrep -f play_full_run`): the lanes compete for CPU and a starved time-budgeted solver plays worse.

**A/B as one batch**: `--arm NAME:KEY=VAL[,KEY=VAL...]` (repeatable) makes the lanes characters x arms (`<Character>/<arm>`, queued Ironclad/a, Ironclad/b, Silent/a, ... so the arms progress together under `--max-lanes`); each lane's env is the base env plus its arm's KEY=VALs, every arm plays the same seeds, kind defaults to `ab`, and per-lane files use `__` for the slash (`Ironclad__value.jsonl`, `games/Ironclad__value/`): `.venv/bin/python python/run_batch.py --name route-ab --games 40 --chars all --ascension 1 --seed-prefix p3b_ --max-lanes 6 --threads 3 --arm random:STS2_ROUTE_POLICY=random --arm value:STS2_ROUTE_POLICY=value`.

`play_full_run.py` runs the **greedy** out-of-combat policy by default since 2026-10-12 (`STS2_OOC_POLICY=greedy`; see Protocol notes), so this regression exercises `agent.combat_env.greedy_action` for card rewards, rest sites, events, bundles, card selects and shops. Set `STS2_OOC_POLICY=naive` to regress the old placeholder policy as well when a change touches it.

## Setup

```bash
./setup.sh                        # pyenv venv + auto-detect Steam, copy DLLs, IL-patch, build
python3 python/play.py            # auto-setup on first run
```

**Python environment** is managed by pyenv + pyenv-virtualenv:
- `.python-version` pins the virtualenv `sts2-cli` (based on Python 3.11.12)
- `setup.sh` auto-installs pyenv, pyenv-virtualenv, Python, creates the venv, and installs dependencies
- Dependencies: `pytest` (for tests), `requirements-agent.txt` (for RL/LLM agents)

**Always use `.venv/bin/python`** for any Python invocation in this repo (training, eval, coordinator, scripts). The system `python3` lacks the project deps (`tensorboard`, `sb3-contrib`, etc.) and will fail with `ModuleNotFoundError`. Either `source .venv/bin/activate` once per shell or invoke as `.venv/bin/python ...` directly.

**IL patcher** (the Cecil C# heredoc in `setup.sh`): the CLR rejects bad IL only when a method is first JIT-compiled, i.e. mid-game (BUG-054: Cecil truncated short branches that patch 4 pushed out of range -> `InvalidProgramException` in `SandpitPower.UpdateCreaturePositions`). After editing it run `.venv/bin/python tools/check_il_patch.py --repatch` (patches a COPY of `lib/sts2.dll.original`, JIT-compiles every method, fails on any the original compiles and the patched one does not; never touches `lib/`). `setup.sh` runs the same check at the end.

## Scratch / Temp Scripts

One-off scripts (perf probes, debugging, experiments) go to `/tmp/sts2-cli/`, NOT the repo root. Only promote to the repo after the script has been used repeatedly and proven useful.

```bash
mkdir -p /tmp/sts2-cli
# write throwaway scripts here, e.g. /tmp/sts2-cli/test_speed.py
```

Rationale: keeps the repo clean of dead scratch files; promotion is an explicit signal that something deserves version control.

## Architecture

```
Your Code (Python / JS / LLM)
    │  JSON stdin/stdout  OR  HTTP (sts2_bridge.py)
    ▼
src/Sts2Headless (C# .NET 9)    ← Program.cs + RunSimulator.cs
    │  Harmony IL patches
    ▼
lib/sts2.dll (game engine, IL-patched)
  + src/GodotStubs (replaces GodotSharp.dll)
```

**Key design choices:**
- **Synchronous execution**: Harmony patches replace `Task.Yield`/`Cmd.Wait()` calls in the game engine with no-ops, allowing the async game loop to run synchronously.
- **`InlineSynchronizationContext`**: Custom `SynchronizationContext` that posts continuations back to the main thread inline, enabling single-threaded headless operation.
- **Bilingual output**: Every card, relic, enemy, and event name is returned as `{"en": "...", "zh": "..."}` using JSON lookup tables in `localization_eng/` and `localization_zhs/`.

## Sts2Advisor (in-game advice mod)

A real-game mod (`src/Sts2Advisor/`) that shows out-of-combat advice plus its reasons in a bottom-right panel; combat is left to the CombatSolver Workshop mod. Spec `docs/superpowers/specs/2026-10-21-sts2-advisor-mod-design.md`, plan `docs/superpowers/plans/2026-10-21-sts2-advisor-mod.md`. `<user dir>` below is `~/Library/Application Support/SlayTheSpire2/Sts2Advisor/`.

- **Install / update**: `tools/install_advisor_mod.sh` (builds against the real Steam `sts2.dll`/`GodotSharp.dll`, copies into `SlayTheSpire2.app/Contents/MacOS/mods/Sts2Advisor/`, writes `<user dir>/config.json` once). Re-run after a Steam update or file verification. The script refuses to install while the game runs (overwriting the loaded DLL corrupts it mid-game, seen 2026-11-03; `STS2_INSTALL_WHILE_RUNNING=1` overrides). Log: `<user dir>/Sts2Advisor.log`; every decision sent and reply received: `<user dir>/advisor_trace.jsonl` (rotates at 20 MB to `advisor_trace.1.jsonl`).
- **Capture**: `src/Sts2Advisor/DecisionCapture.cs` reads the current screen with `ActiveScreenContext.Instance.GetCurrentScreen()`, polled every 0.3 s on the main thread; the sidecar is asked only when a decision's fingerprint was the same on two polls in a row (screens animate in). Single-player only: co-op shows "联机/Multiplayer" and no advice. `F8` (config `hotkey`) toggles the panel; on a Mac laptop F8 is the media key, so Fn+F8.
- **Advice** comes from `agent/advisor_server.py` (127.0.0.1:8767): `greedy_action(state, trace=GreedyTrace())` — the same policy and defaults as `play_full_run` — plus the trace of that same call. `agent/greedy_trace.py` `TRACE_KEYS` and `src/Sts2Advisor.Core/TraceText.cs` must list the same keys (`tests/test_advisor_trace_text_keys.py`). A greedy change must keep `tests/agent/test_greedy_golden.py` passing; an intended behaviour change regenerates `tests/fixtures/advisor/ooc_corpus.jsonl.gz` with `tools/build_advisor_corpus.py` and says why in the commit. The advice service runs with `STS2_CARD_QUALITY_GATE=0` (`advisor_server.advisor_env_defaults`, since 2026-11-03; an explicit env value wins, startup log `card quality gate: off (advisor default)`, no panel warning): in real games the act-1 gate skipped 149/165 late-act-1 card rewards incl. 43 act-1 boss rewards, and its July evidence predates the engine fix. The headless default stays on until a paired A/B, so advice differs from `play_full_run` there.
- **Sidecar lifecycle**: the mod starts `agent/advisor_server.py --exit-on-stdin-eof` (or reuses a server already answering `/health` on the port); the flag makes the service exit when the game dies. **Hot reload**: the mod also passes `--reload-on-commit`; a daemon thread polls `git rev-parse HEAD` every 30 s and, once HEAD differs from the HEAD at startup *and* `git status --porcelain --untracked-files=no -- agent/ python/ data/` is clean, waits for the request in flight, logs `[advisor_server] hot reload: <old> -> <new>` (in `Sts2Advisor.log`) and `os.execv`s itself with the same argv/env/stdin pipe -- so **commit a policy change and it is live in the running game within ~30 s; uncommitted edits never load** (HEAD moved but the tree dirty = one log line, then it waits). The new image re-runs the warm-up, so the port refuses connections for ~2.5 s (8 s on a cold, loaded machine); the mod treats that as offline and reconnects by itself (panel backoff 1-2-4 s; the autopilot retries every second and only stops after 10 s of outage). `/health` `commit` is the post-reload HEAD. A server started by hand without the flag, or left over from before it existed, keeps serving old code until killed (`pkill -f advisor_server.py`); the flag takes effect for a sidecar the next time the *game* launches it, since an already-running one is reused as is.
- **Failure behaviour**: a screen whose reading throws 3 times in a row is parked (panel says read failed) until the player is on another screen or that screen's state changes. `TypeLoadException`/`MissingMemberException` disable the mod for the session and the panel shows "游戏版本未适配".
- **Autopilot (全托管)**: F9 (config `autopilot_hotkey`) or the panel's 全自动 button hands the rest of the run to `src/Sts2Advisor/AutoPilot/`; F10 (`step_hotkey`) or 执行这一步 runs a single step -- one advised choice plus whatever needs no decision, stopping at the next decision (`StopReason.StepDone`). Any two equal hotkeys (with `hotkey`) disable the autopilot (the panel toggle still works). Config `instant_mode: true` makes `InstantMode.cs` set `PrefsSave.FastMode = Instant` (what the dev console's `instant` does; release builds reset it at startup) once the main menu or a run is up, and re-apply it every few seconds if the game resets it.
  - It clicks every out-of-combat decision greedy advises and stops at the result screen, on F9, or on anything it cannot handle. The panel says why it stopped. The panel ignores the mouse except on its buttons, which never take keyboard focus.
  - Combat is left to the CombatSolver mod's full-auto. The autopilot only warns when `combat_solver_settings.json` has `autoEnableFullAuto` off, and it never touches a screen while combat is in progress.
  - **Full potion belt**: a combat reward's potion used to be left behind (the game refuses it without a free slot). `RewardsHandler` now asks `POST /potion_swap` (`agent/potion_swap.py`: greedy's shop potion score + `KEEP_BONUS`, Fairy in a Bottle on top; swaps only when the offered potion scores >= 2.0 above the worst held one), discards that potion the way `NPotionPopup` does (`DiscardPotionGameAction` through `RunManager.ActionQueueSynchronizer`), waits for the slot, then claims the reward; recorded as a step + `potion_swap` trace lines. Any failure logs once and skips the reward as before. Live-game behaviour unverified until a run hits a full belt.
  - Screens with no advice (choose a relic, crystal sphere) and modals (first-time tips) are handed to the player; the autopilot resumes once they close. The open map wins over the overlay stack, as in `ActiveScreenContext` (`AutoPilotScreenOrder`: game over > modal > combat > map > overlay > room): `NRewardsScreen` stays in the stack under the map after Proceed, and a map that stays closed to travel for 2 s is the player's.
  - It reuses the game's own AutoSlay handlers but **never calls `AutoSlayer.Start()`**, which abandons the run, writes unlocks to the save and quits the game.
  - Deck/card select screens (upgrade, transform, enchant, deck select, simple select): `NCardGrid` is virtualised (holders exist only for the rows in view), so `GridSelectHandler` presses the advised card's holder when there is one and otherwise selects it through the screen's own `OnCardClicked(CardModel)` (the end of the holder's signal path; protected abstract, called by reflection). Picked cards the grid does not show are logged (`has no holder on screen`).
  - `HandlerPatches` transpiles 9 handlers' `MoveNext`: `NextItem` becomes `AutoPilotChoice.Pick`, and the cheating `EventRoomHandler.HandleEventCombat` (+100 Strength, kills the enemies) becomes a wait. A game update that changes those call counts disables the autopilot (logged at load as `autopilot disabled, AutoSlay handlers not patched`).
  - It never changes game speed. For speed, use CombatSolver's 瞬间 setting or SpeedX.
  - **Step pause**: after each full-auto step the loop waits `step_pause_seconds` (config, default 2.5, clamped 0..10, 0 = off; missing in an older `config.json` = 2.5) before acting on the next screen, at the top of `StepAsync` and in `FetchAdviceAsync` (shop purchases and event pages never return to `StepAsync`). A single step (F10) is never held. The newest step's panel line is followed by muted lines with what it chose, in the game's current language: a card (`CardModel.GetDescriptionForPile(PileType.None)`; for a smith pick the upgraded clone's `GetDescriptionForUpgradePreview()`, as `NCardLibrary` does), relic or potion (`DynamicDescription.GetFormattedText()`); `DescriptionText.Plain` strips the BBCode (the panel escapes `[`, so nothing could render), turns energy/star icons into words and cuts at 140 characters.   - Executed steps are in `advisor_trace.jsonl` as `"autopilot": {"executed": true, "step": n}`; stops are `decision: autopilot_stop` lines.
  - **Campaign mode** (unattended chain of runs, `src/Sts2Advisor/Campaign/`): `<user dir>/campaign.json` = `{"enabled": true, "next": {"character": "IRONCLAD", "ascension": "max" | 6}, "rotation": [...], "command": null | "quit" | "stop"}`, re-read once a second (missing/empty/disabled = off; an unusable file is off and the panel says why). Character ids: IRONCLAD, SILENT, DEFECT, REGENT, NECROBINDER; `"max"` = the character's `CharacterStats.MaxAscension` (0 until its ascension epoch is revealed, as in the lobby), a higher number is clamped and logged. **`rotation`** (optional) is a list of `{"character": "REGENT", "ascension": "max" | n}` entries (a plain `"REGENT"` string, or an object without `ascension`, means max); when it has entries it decides the next run and `next` is ignored: the entry after the first one whose character matches the run that just ended (cycling; a character that is not in the list, or no run ended yet, starts at the first entry -- list each character once). The ended run's character is the last line of `campaign_runs.jsonl` (read at game start, so a restart goes on from the right place), so it is a function of the character alone: continuing a saved run advances nothing, and an edit of the list is seen by the next start. **`"strategy": "ladder"`** (with `"characters": ["NECROBINDER", "REGENT", "IRONCLAD"]`, known ids each once, order = tie-break; `next` and `rotation` are then ignored; an unknown/duplicate name or a missing list makes the file invalid with a panel warning; `src/Sts2Advisor.Core/CampaignLadder.cs`) plays the characters up one shared ladder: a character is DONE when the game's run history has a win at ascension >= 10 for it (`<profile>/saves/history/*.run`, the modded profile's while mods load -- `win`, `ascension`, `players[0].character`; scanned each tick, each file parsed once); level = the character's max unlocked ascension capped at 10; the pick is the minimum level among the not-done characters, and the character of the last ended run (last line of `campaign_runs.jsonl`) plays again iff it is eligible AND that run was a LOSS AND its level is still the minimum ("keep playing it until it clears"); otherwise the first listed character at the minimum level (so a win, which moves the character up, is never sticky). It starts the pick at `"max"` and logs `campaign: ladder pick NECROBINDER a9 (levels N9 R9 I10; sticky after loss)`; all done -> `campaign: ladder complete` and no new run. The panel's campaign line adds `ladder N9 R9 I10 done`. While enabled: a run in progress with the autopilot off -> full auto; a run that ends -> one line in `<user dir>/campaign_runs.jsonl` (`ts, character, ascension, victory, act, floor, total_floor, hp, max_hp, gold, deck` as `CARD.X+1`, `relics, potions, run_time, seed, killed_by, killed_by_event, killed_by_monsters, history_path, start_time`) and a `decision: "run_end"` trace line, then the game-over screen is clicked through to the menu (the timeline the game opens after a run that discovered epochs is worked through best-effort). A victory's summary (score lines, badges) can take 30 s or more. **A victory's HP** comes from the game's saved `<start_time>.run` (last map point entry): the Architect's `WinRun` calls `OnEnded(true)` (entry filled, file saved) and then kills the player, and killing the last player calls `OnEnded(false)`, whose `UpdatePlayerStatsInMapPointHistory` rewrites that same in-memory entry (shared with `RunManager.History`) with HP 0; so the live player and the in-memory entry both read 0. Runs recorded before this fix have `hp: 0` for wins (the `history_path` file has the real value), and at the main menu a saved single-player run is Continued (never abandoned) or the next run is started with `NGame.StartNewSingleplayerRun` -- the call the character-select Embark ends in -- with a random seed. Autopilot Stuck/HandlerFailed/BadReply stops are restarted 10 s later once per floor (a second stop on that floor logs `campaign: needs attention` and stays stopped), an unreachable advice service (Offline) is restarted as attempts allow, a hand stop (F9 / Stop) is respected until the file changes; a popup open for 5 s is closed if it is a first-time tip, an error popup or the early-access note; a screen the autopilot hands to the player (choose a relic, crystal sphere) for 60 s is played by AutoSlay's own handler (a random pick) so nothing parks the night. Nothing repeats faster than 4, 8, 16, 32, 60 s; the fifth unsuccessful attempt logs `campaign: stuck: <why>` and the campaign stays stopped until the file changes (the panel's campaign line says so). A change of `next`/`rotation` never cancels a flow under way (finish run, start run, continue ...): only `enabled: false`, `"command": "stop"` and `"command": "quit"` interrupt one, and the new values are read when they are needed. `"command": "stop"` turns the autopilot off and does nothing until the file changes; `"quit"` preempts everything, on any screen including the game-over screen (a run that ended is recorded first), cancels the flow under way, rewrites the file with `"command": null` first (no quit loop; no rewrite = no quit) and then calls `NGame.Quit()` (what the menu's confirmed Quit calls); a start-run flow past its fade-out finishes first. Every transition is a `campaign: ...` line in `Sts2Advisor.log`. Pure parts (`CampaignFile/Plan/Rotation/GameOver/Vitals/Attempts/RunLog/Text`) are in Core with tests; the game-facing parts ran live on 2026-11-02 (the first victories exposed the edit-cancels-flow retry loop, `hp 0` for wins and quit-not-working-on-the-game-over-screen, all fixed); the resumable click-through, `rotation` and the `ladder` strategy have not been run live yet.

The paired headless A/B (a5, 43 pairs, Ironclad + Defect, `STS2_ROUTE_POLICY` arms) measured lookahead **+5.42 floors (se 1.91, t 2.84), wins 12 -> 17**; the panel footer then reads "整条路线前瞻（A/B：a5 43 局 +5.4 层） / whole-path lookahead (A/B: a5, 43 pairs, +5.4 floors)" (keyed on the `map.la_best_path` rule; a `map.la_fallback` -- no map, an offered node off the map -- or a single-choice node keeps the next-step-only text). `advisor_server.knob_warnings` treats `STS2_MAP_POLICY=lookahead` as the advisor's own expected setting (`EXPECTED_SETTINGS`, no warning); any other non-default value still warns. `WithFullMap` also adds `decision["ascension"]` (the shared serializer carries none): `LookaheadMapStrategy` picks its per-room HP cost table by it (`COST_BANDS`: ascension <= 5 = the original table exactly, 6-7 and >= 8 = real-game autopilot damage per room, evidence in the class comment; no ascension in the decision, as in the headless engine, = the original table), and `map.la_best_path` records the `cost_band`. A failed map read (logged, `reading the full map failed`) just omits the key: routing falls back to HpAware one step ahead.   ```

## JSON Protocol

Commands sent via stdin, one JSON object per line:

```json
{"cmd": "start_run", "character": "Ironclad", "seed": "test", "ascension": 0}
{"cmd": "action", "action": "play_card", "args": {"card_index": 0, "target_index": 0}}
{"cmd": "action", "action": "end_turn"}
{"cmd": "action", "action": "select_map_node", "args": {"col": 3, "row": 1}}
{"cmd": "action", "action": "skip_card_reward"}
{"cmd": "quit"}
```

Decision point types returned: `map_select`, `combat_play`, `card_reward`, `card_select`, `rest_site`, `event_choice`, `shop`, `bundle_select`, `treasure`, `game_over`.

A typical run starts with a Neow `event_choice` — agents must handle this initial event before reaching `map_select`.

## Conventions

- **Progress notation — `A<act>F<floor>a<ascension>`**: e.g. `A2F12a10` is act 2, floor 12, ascension 10. **Case carries the meaning**: upper-case `A` is the act, lower-case `a` is the ascension. Acts and floors are 1-based (`global_floor 41` → `A3F7`, i.e. `((floor-1)//17)+1`). Emit only the parts you actually have — a training batch has an ascension but no act or floor, so it is labelled `a0`, or `a?` when the ascension was never recorded. Never write a bare `A0` for an ascension; it reads as an act.
- **Event completion**: trust `localEvent.IsFinished`. Never gate on "option count unchanged after a choice" — events legitimately loop on the same page (Slippery Bridge Hold On) and post-selection continuations (heal/enchant/add-card) often run on the same options page; force-finishing kills them silently.
- **Async selection continuations**: any path whose effect can open a card_select / card_reward / bundle (event option, shop relic pickup, etc.) must run on `Task.Run(...)` and yield as soon as `_cardSelector.HasPending` / `HasPendingReward` / `_pendingBundles != null` appears. The Task completes naturally once the external `select_cards` feeds the selector's TCS. Reference shape: `DoChooseOption`, `DoBuyRelic`.
- **DynamicVar preview during serialization**: `UpdateDynamicVarPreview` mutates the live card. Bracket reads with `ClearPreview` **before and after** — leaving the card in preview state corrupts subsequent play actions (Momentum Strike `PlayCardAction` failure).

## Protocol notes

- `card_select` decision uses key `cards` (not `options`) and action `select_cards` with comma-separated `indices`.
- `AnyEnemy` cards/potions require `target_index` when ≥2 enemies are alive; with a single alive enemy the adapter auto-targets.
- `plan_combat_turn` action (at a `combat_play` decision) returns a multi-turn plan from the ported Combat Solver engine (`src/Sts2Headless/CombatSolverEngine/`, vendored — see its `VENDORED.md`; never hand-edit it). Unlike every other action in this file, its actions address things by **stable identity, not position**: cards by `card_id`/`card_occurrence` (not hand `card_index`), enemies by `target_combat_id` (matches the `combat_id` field on each enemy in the `combat_play` decision; positional `target_index` goes stale as soon as an earlier action kills an enemy), potions by `potion_id` (matches each potion's `id`; the plan's `potion_slot` is the physical belt slot, which differs from `potion_index` once any earlier slot is used). `python/combat_plan_driver.py` resolves all of these against the live decision — reuse it rather than re-deriving indices. **Only execute the actions up through the plan's first `end_turn`, then re-call `plan_combat_turn` fresh** — the plan's later turns assume draws and intents the protocol does not expose. If a planned card is not in the live hand (the solver's prediction drifted), stop and re-plan; that is expected, not an error.
- `plan_combat_turn` costs ~3.4 s median / ~9 s mean per call at the default 120 s soft budget (`SolverSearchProfile.Default` — the only profile; 8 threads, one process) versus ~0.01 s for the heuristic, so a solver-driven game takes minutes. `STS2_SOLVER_BUDGET` selects the budget: **only `30`/`60`/`120`/`180`/`300` (seconds)**, unset = 120; anything else warns in the engine and raises in `play_full_run.py` before a game starts, and `play_full_run.py` fails a run if the engine reports a different budget (or none — a stale build). Measured (`docs/superpowers/plans/2026-09-23-combatsolver-phase2b1-budget-tiers.md`): 30 s is non-inferior to 120 s for Ironclad/Silent/Defect/Necrobinder and cuts batch solve time 13–55% (Regent still undecided); 300 s buys nothing, because longer searches stop at the 120 000-node cap (`MaxExpandedNodes`) instead. Every `combat_plan` reply carries `search.{budget_ms, elapsed_ms, boundary, expanded_nodes, total_expanded_nodes}`; `boundary == "TimeLimit"` under-counts time-capped searches (it is the chosen line's boundary), so compare `elapsed_ms` with `budget_ms`.
- `STS2_SOLVER_INFERRER` switches the solver's IL card-effect inferrer (`CardOnPlayInferrer`, restored in BUG-048): `on` (default; unset/blank/`1` too) is the real solver, `off`/`0` reproduces the pre-BUG-048 stub (no simulated Attack/Block/Draw for the ~486 cards without a hand-written mirror) and is for paired A/Bs only. The engine tolerates an unknown value (on + a stderr warning); `play_full_run.py` raises on it before any game starts. The engine reports its mode as `combat_plan.search.inferrer` (`"on"`/`"off"`) and `play_full_run.py` cross-checks it against its own resolution on every plan, failing the run on a mismatch or a missing field (stale build); every result and `--results-log` row carries `solver_inferrer`.
- A `plan_combat_turn` call can **hang indefinitely** (`agent/bug.md` BUG-040 — reproducible: Ironclad seed `run_32` hangs at the A1F17 boss): the budget is only checked between search-node expansions. `python/play_full_run.py` guards against it through `python/engine_process.py`: every engine reply has a deadline (`plan_combat_turn`: budget + 60 s; anything else: 120 s), and a miss kills the engine's whole process group (the real engine is a child of `dotnet run`) and records the game as `HANG` (paired_eval status `stuck`). **`tests/conftest.py`'s Game fixture and `agent/sts2_bridge.py` start the engine without this protection.**
- `python/play_full_run.py` routes combat through `plan_combat_turn` for the characters in `STS2_SOLVER_CHARS` (comma list / `all` / `none`; default all five — a paired A/B measured +4.7..+10.5 floors on every character, see `docs/superpowers/plans/2026-09-21-combatsolver-port-phase2.md`). `STS2_SOLVER_CHARS=none` is the heuristic control arm; an unknown name raises rather than silently disabling the solver. `STS2_SOLVER_THREADS` pins the solver's search threads (default 8 on an 18-core machine) — set it when running several solver processes at once, because a time-budgeted search starved of CPU plays measurably worse. The SUMMARY prints per-run `solver=<plans>/<attempts>` and a `SOLVER NEVER ENGAGED` banner if a solver-enabled character got zero plans, since a batch that silently fell back to the heuristic still reports `Completed: N/N`. `--results-log <file>` writes `agent/paired_eval.py` input rows.
- The engine's `floor` field is **act-local** (resets to 1 each act). Anything comparing runs across acts must use the global floor `(act - 1) * 17 + floor` (`agent/eval_rl.py` `global_floor_from_state`). `play_full_run.py`'s `avg_floor` was act-local until a6472da — older numbers only compare between runs that died in the same act.
- `python/play_full_run.py` out-of-combat decisions (card_reward, rest_site, event_choice, bundle_select, card_select, shop) follow `STS2_OOC_POLICY`: `greedy` = `agent.combat_env.greedy_action` (**default since 2026-10-12** — a1 paired A/B, inferrer on, 40 seeds × 5 characters, naive → greedy: Ironclad +8.71 floors p=0.0004, win 13%→58%; Defect +5.13 p=0.011, 25%→57.5%; Necrobinder +8.09 p=0.0005, 9%→46%; Regent +0.25 p=0.93, 16%→28%; Silent +1.93 p=0.38, 5%→7.5%; none significantly worse; record `~/.sts2-train/ab3_20261009_064743/analysis_final.txt`, plan `docs/superpowers/plans/2026-09-30-phase3a-ooc-policy-port.md`), `naive` = the old placeholders (card 0, always HEAL, never shop), kept as the control arm; blank/unset = greedy, unknown values raise. `map_select` stays a seeded random route and `combat_play` stays on the solver. `--ascension N`, `--seed-prefix P` (default `run_`) and `--keep-game-logs DIR` exist for experiments; **`logs/` is purged after 7 days** (`game_log.cleanup_old_logs`), so any game log an analysis needs must be kept with `--keep-game-logs`. Numbers measured before 2026-10-12 without `STS2_OOC_POLICY` ran the naive policy.
- `python/play_full_run.py` `map_select` follows `STS2_ROUTE_POLICY`: `random` (**default; blank/unset = random**, unknown values raise) = a seeded random child; `value` = the Phase 3b planner (`agent/route_planner.py`: enumerate every path to the boss, step the expected state with the empirical transition cells, score the end state with the linear value model from `STS2_ROUTE_MODEL`, default `agent/data/route_model_a1.json`). **`value` lost its A/B and stays off** (2026-10-16, batch `logs/batches/p3b-route-ab-20261012-160225`, a1, 40 seeds × 5 characters, random → value: Ironclad −4.95 floors p=0.016, A2 boss pass 78%→50%; Silent −1.11 p=0.45; Defect +0.92 p=0.47; Regent +1.44 p=0.58; Necrobinder −0.69 p=0.71; pooled floors −0.93 p=0.28 but **wins 62→39 of 191 pairs, p=0.003**; plan `docs/superpowers/plans/2026-09-30-phase3b-route-value-planner.md`). The transition model is fine (relics/deck predicted ~unbiased); the value model is not causal — it pays for hoarded gold (+0.66 floors/SD) and scores bigger/stronger decks lower, so the planner skips shops (~0.6–0.9 → ~0.2–0.4 per act) and elites (A2 ~1.6 → ~0.5–1.2) for rest sites, then reaches the bosses with the same HP but fewer relics and unspent gold. Don't retune its knobs; a route value needs monotone/causal structure or rollout values. Value-arm logs are tagged `route=value` in `run_meta.experiment` and are skipped by `agent/fit_route_model.py` unless `--allow-value-logs`.
- **`STS2_ROUTE_POLICY=hpaware|lookahead`** (2026-11-02) play `map_select` through `agent.combat_env.greedy_action`, i.e. what the in-game Sts2Advisor autopilot does, for a paired headless A/B (`--arm hp:STS2_ROUTE_POLICY=hpaware --arm la:STS2_ROUTE_POLICY=lookahead`; both arms pass the map policy to `greedy_action` explicitly, so a stray `STS2_MAP_POLICY` cannot change an arm). `hpaware` = `HpAwareMapStrategy` (next node only; no `get_map`). `lookahead` = `agent.strategy.LookaheadMapStrategy`: fetches `get_map`, attaches it as `state["map"]`, enumerates every path from each offered node to the boss (`route_planner.enumerate_paths`), simulates expected HP room by room (rests heal 30% under `rest_site_action`'s threshold, else smith; fights cost HP by act) and adds each combat's chance of dying at the HP the path arrives with (death curves read off `route_model_a1.json`: death rate vs HP / mean cost), so a corridor that forces an elite at low HP loses to a fork that avoids it. Constants and their evidence are at the top of the class (a first-guess tuning -- 12 pts per elite, 400 per death -- that only an A/B can confirm); without a usable map it IS `HpAwareMapStrategy`. Single-choice map_selects are `route_forced` (no `get_map`); `route_plans` counts engaged picks, `route_fallbacks` lookahead-without-map (HpAware's pick) or a greedy_action exception (seeded random); the summary prints `!! LOOKAHEAD NEVER ENGAGED` if no pick was planned. Both arms tag `run_meta.experiment` `,route=<policy>` and `fit_route_model` skips them. `STS2_MAP_POLICY=hpaware|lookahead` (default hpaware; in `GREEDY_BEHAVIOR_ENV`) is the same switch for `greedy_action` callers; the in-game advisor now sends `state["map"]` too (config `map_policy`, see the Sts2Advisor section).
- `python/play_full_run.py` game logs carry the run metadata the workbench (`agent/run_progress_viewer.py`, :8765) files and compares batches by: the `run_meta` header has `game_version` + `game_version_source` (`--game-version` → `cli`; `$STS2_GAME_VERSION` → `environment`; else `<STS2_GAME_DIR>/../release_info.json` → `release_info`, via `agent.run_metadata.resolve_optional_game_version`; unresolved = omitted + one warning, never a failed run), `evaluation_mode: fixed`, `scenario: full_run`, a strict-bool `is_multiplayer: false` (the replay adapter reads it from this header; without it the run's map view says "Multiplayer flag must be a boolean"), `experiment: <batch>:ooc=<policy>` (batch = `--experiment NAME`, else `--seed-prefix` minus its trailing `_`, so each seed prefix is its own cohort) and a per-game `run_id` (`pfr-<12 hex>`) that is also on the result and the `--results-log` row. Old logs without these land in the workbench's "未知版本（未归档）" cohort. The workbench's full-map view does NOT read map snapshots from game logs (only deck-history `map_snapshot` rows), and its map generator supports only `v0.103.2`, so a `v0.111.0` run shows the recorded route only.
